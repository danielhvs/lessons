dpkg vs apt

Two layers of the same machine: apt plans and fetches, dpkg installs. Every command below ran on Ubuntu 24.04 (apt 2.8, dpkg 1.22.6), with one example package all the way through: fortune-mod.

1The problem

A package is a program's files plus a label, installed as one unit. On Debian and Ubuntu it ships as a .deb file. Most packages need other packages to work: their dependencies. Install a .deb with the low-level tool alone and it stops halfway as soon as one dependency is missing, leaving a package that is on disk but not usable. You then have to find, download and install every missing piece yourself, in the right order.

That is the job split: dpkg installs the .deb files you hand it and never downloads anything. apt finds packages in the repos (repositories: servers that host packages plus an index of them), works out the dependencies, downloads them, and then runs dpkg itself.

2The smallest example: apt calls dpkg

They are not rivals. apt's own configuration names the dpkg binary it runs for every install and removal:

apt-config dump | grep Dir::Bin::dpkg Dir::Bin::dpkg "/usr/bin/dpkg";

3A .deb is a box with a label

A .deb holds the program's files plus a control file: its label, with name, version and the packages it needs. apt download fetches a .deb without installing it, no root needed. dpkg-deb --info reads the label:

apt download fortune-mod Fetched 32.7 kB in 1s (42.7 kB/s) dpkg-deb --info fortune-mod_1%3a1.99.1-7.3build1_amd64.deb Package: fortune-mod Version: 1:1.99.1-7.3build1 Depends: libc6 (>= 2.34), librecode0 (>= 3.6) Recommends: fortunes-min | fortune-cookie-db Description: provides fortune cookies on demand

Depends: lists what the package cannot run without. Recommends: lists what usually comes along: apt installs those by default, dpkg ignores them.

4dpkg alone: unpacks, then stops

Hand the .deb straight to dpkg. It does two things in order: unpack (copy the files into place) and configure (run the package's setup scripts, which needs every dependency installed). It unpacks, sees librecode0 is missing, and refuses to configure. It does not go and fetch librecode0.

sudo dpkg -i fortune-mod_1%3a1.99.1-7.3build1_amd64.deb Unpacking fortune-mod (1:1.99.1-7.3build1) ... dpkg: dependency problems prevent configuration of fortune-mod: fortune-mod depends on librecode0 (>= 3.6); however: Package librecode0 is not installed. dpkg: error processing package fortune-mod (--install): dependency problems - leaving unconfigured dpkg -l fortune-mod | tail -1 iU fortune-mod 1:1.99.1-7.3build1 amd64 provides fortune cookies on demand

The first two letters of dpkg -l are the status. iU: you want it installed (i), but it is only Unpacked (U). A healthy package shows ii.

To finish with dpkg only, you fetch the dependency yourself and install it. That does not fix fortune-mod on its own: it stays iU until you tell dpkg to configure whatever is still waiting.

sudo dpkg -i librecode0_3.6-26_amd64.deb Setting up librecode0:amd64 (3.6-26) ... dpkg -l fortune-mod librecode0 | tail -2 iU fortune-mod 1:1.99.1-7.3build1 ii librecode0:amd64 3.6-26 sudo dpkg --configure -a Setting up fortune-mod (1:1.99.1-7.3build1) ... dpkg -l fortune-mod | tail -1 ii fortune-mod 1:1.99.1-7.3build1

These dpkg runs happened in a throwaway root (dpkg --root), so the real system stayed clean; the messages are dpkg's own.

5apt: the same install, one command

apt reads Depends: and Recommends: from its index, adds librecode0 and the recommended fortunes-min, downloads all three, and runs dpkg on them, dependencies first. -s simulates: it prints the plan without doing it, so it needs no root.

apt-get -s install fortune-mod The following NEW packages will be installed: fortune-mod fortunes-min librecode0 0 upgraded, 3 newly installed, 0 to remove and 94 not upgraded. Inst librecode0 (3.6-26 Ubuntu:24.04/noble [amd64]) Inst fortune-mod (1:1.99.1-7.3build1 Ubuntu:24.04/noble [amd64]) Inst fortunes-min (1:1.99.1-7.3build1 Ubuntu:24.04/noble [all]) Conf librecode0 (3.6-26 Ubuntu:24.04/noble [amd64]) Conf fortune-mod (1:1.99.1-7.3build1 Ubuntu:24.04/noble [amd64]) Conf fortunes-min (1:1.99.1-7.3build1 Ubuntu:24.04/noble [all])

Inst means dpkg unpacks the package, Conf means dpkg configures it.

6Got a .deb file? Still use apt

Give apt the path, with ./ so it reads it as a file and not as a package name. It installs your .deb and still fetches the dependencies from the repos. local-deb marks the package taken from your file.

apt-get -s install ./fortune-mod_1%3a1.99.1-7.3build1_amd64.deb fortune-mod fortunes-min librecode0 Inst librecode0 (3.6-26 Ubuntu:24.04/noble [amd64]) Inst fortune-mod (1:1.99.1-7.3build1 Ubuntu:24.04/noble, local-deb [amd64]) Inst fortunes-min (1:1.99.1-7.3build1 Ubuntu:24.04/noble [all])

Already stuck at iU from a raw dpkg -i? sudo apt -f install (--fix-broken) installs the dependencies the stuck package waits for, then configures it.

sudo apt -f install

7Removing: dpkg refuses, apt cascades

dpkg -r will not remove a package something else depends on:

sudo dpkg -r librecode0 dpkg: dependency problems prevent removal of librecode0:amd64: fortune-mod depends on librecode0 (>= 3.6). dependency problems - not removing sudo dpkg -r fortune-mod Removing fortune-mod (1:1.99.1-7.3build1) ... dpkg -l fortune-mod | tail -1 rc fortune-mod 1:1.99.1-7.3build1 amd64

rc: removed, but its config files are still on disk.

apt lists every package that has to go with it and asks before acting. On this machine, removing one small perl library takes ubuntu-minimal with it:

apt-get -s remove libtext-charwidth-perl The following packages will be REMOVED: debconf-i18n libtext-charwidth-perl libtext-wrapi18n-perl ubuntu-minimal 0 upgraded, 0 newly installed, 4 to remove and 94 not upgraded.

1 asked, 4 removed. Read that list before saying yes.

8Asking questions: two databases

dpkg answers about what is installed on this machine, from its own database. apt answers about what the repos offer, from its index.

dpkg -S /usr/bin/ls coreutils: /usr/bin/ls dpkg -L coreutils | grep -E 'bin/(ls|cat)$' /usr/bin/cat /usr/bin/ls apt-cache policy librecode0 librecode0: Installed: (none) Candidate: 3.6-26

dpkg -S: which package owns this file. dpkg -L: which files this package put down. apt-cache policy: installed version vs the candidate, the version apt would install.

9A new example: toilet

The same rule on a package not seen yet. toilet prints big text banners. Its Depends: line has three entries; two are already installed here:

apt-cache show toilet | grep Depends Depends: libc6 (>= 2.34), libcaca0 (>= 0.99.beta20), toilet-fonts dpkg-query -W -f='${db:Status-Abbrev} ${Package}\n' libc6:amd64 libcaca0:amd64 toilet-fonts dpkg-query: no packages found matching toilet-fonts ii libc6 ii libcaca0

dpkg-query -W is the query behind dpkg -l; ${db:Status-Abbrev} prints the same status letters.

So apt adds exactly one package to the one you asked for, and puts it first:

apt-get -s install toilet The following NEW packages will be installed: toilet toilet-fonts 0 upgraded, 2 newly installed, 0 to remove and 94 not upgraded. Inst toilet-fonts (0.3-1.4build1 Ubuntu:24.04/noble [all]) Inst toilet (0.3-1.4build1 Ubuntu:24.04/noble [amd64]) Conf toilet-fonts (0.3-1.4build1 Ubuntu:24.04/noble [all]) Conf toilet (0.3-1.4build1 Ubuntu:24.04/noble [amd64])

10Common mistakes

sudo dpkg -i some.deb with a dependency missing: the package is left iU, on disk but not configured. Fix: sudo apt -f install, or install the .deb with sudo apt install ./some.deb from the start.

apt install some.deb without ./: apt reads the argument as a package name to look up in the repos: E: Unable to locate package fortune-mod_1%3a1.99.1-7.3build1_amd64.deb. Fix: always give a path, ./some.deb.

Saying yes to apt remove without reading the list: one small library can take a meta-package like ubuntu-minimal with it. Fix: run apt-get -s remove pkg first, or read the REMOVED list before typing y.

Installing the missing dependency and expecting the stuck package to work: it stays iU. Fix: sudo dpkg --configure -a (or sudo apt -f install, which does both steps).

Summary

  1. apt plans and downloads; dpkg unpacks, configures and removes. apt runs dpkg.
  2. Install and remove with apt: sudo apt install pkg, sudo apt install ./file.deb, sudo apt remove pkg.
  3. Stuck at iU? sudo apt -f install.
  4. Ask about this machine with dpkg: dpkg -l, -L, -S. Ask about the repos with apt: apt-cache policy, apt show.
  5. Status letters: ii healthy, iU unpacked only, rc removed with config kept.
