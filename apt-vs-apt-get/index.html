apt vs apt-get

Know which one to type: apt at the prompt, apt-get and apt-cache in scripts. Real output from Ubuntu 24.04, apt 2.8.4.

1The problem

Ubuntu and Debian give you two ways to install a package: apt install cowsay and apt-get install cowsay. Both work, so it is easy to think they are the same. They are not quite: pick the wrong one and a script prints a warning or breaks after an update, or an upgrade quietly skips your new kernel.

apt is the front end for a person at a terminal. apt-get (install, upgrade) and apt-cache (search, show) are the older front ends, with output kept stable for scripts.

2The smallest example: one engine, two front panels

All three programs link the same library, libapt-pkg: the part that reads the package index, solves dependencies, downloads files and runs dpkg.

ldd /usr/bin/apt /usr/bin/apt-get | grep apt-pkg libapt-pkg.so.6.0 => /lib/x86_64-linux-gnu/libapt-pkg.so.6.0 libapt-pkg.so.6.0 => /lib/x86_64-linux-gnu/libapt-pkg.so.6.0

apt only changes defaults. It reads extra config keys in the Binary::apt scope: keys under binary::apt:: apply only when the program is named apt. apt-config dump prints every setting in effect:

apt-config dump | grep -i binary::apt binary::apt::APT::Color "1"; binary::apt::APT::Get::Upgrade-Allow-New "1"; binary::apt::APT::Keep-Downloaded-Packages "0"; binary::apt::DPkg::Progress-Fancy "1"; binary::apt::DPkg::Lock::Timeout "120"; ... (30 lines in all)

man apt says it in one line: "apt(8) just changes the default value of some options (see apt.conf(5) and specifically the Binary scope)."

3On a terminal: color and progress

Typed at a terminal, apt colors the package name green and shows a progress counter:

apt list cowsay Listing... Done cowsay/noble,noble 3.03+dfsg2-8 all

The color is made of escape codes: hidden bytes that tell the terminal to switch color. script runs a command inside a fake terminal and cat -v prints the invisible bytes as text (^[ is the ESC byte, ^M a carriage return):

script -qc 'apt list cowsay' /dev/null | cat -v ^MListing... 0%^M^MListing... 0%^M^MListing... 0%^M^MListing... Done^M^M ^[[32mcowsay^[[0m/noble,noble 3.03+dfsg2-8 all^M

4Piped into a script: the warning

A pipe (|) sends one program's output into another. When apt's output is not a terminal, it warns on stderr, the error stream that shows on screen but is not passed down the pipe:

apt search ^cowsay$ | cat WARNING: apt does not have a stable CLI interface. Use with caution in scripts. Sorting... Full Text Search... cowsay/noble,noble 3.03+dfsg2-8 all configurable talking cow

apt-cache answers the same search with no warning, in its own one-line format:

apt-cache search ^cowsay$ | cat cowsay - configurable talking cow

A stable CLI is an output format that does not change between versions. man apt: apt "may change behavior between versions", so prefer apt-get and apt-cache in scripts "as they keep backward compatibility as much as possible".

5upgrade: the difference that matters

Same machine, same package index. -s simulates: it prints the plan, needs no root and changes nothing.

apt-get -s upgrade | grep upgraded, 88 upgraded, 0 newly installed, 0 to remove and 6 not upgraded. apt -s upgrade | grep upgraded, 94 upgraded, 11 newly installed, 0 to remove and 0 not upgraded.

apt-get upgrade never installs a new package, so every upgrade that needs one is held back (apt-get prints "kept back"). Here the 6 are kernel packages:

apt-get -s upgrade | grep -A3 'kept back' The following packages have been kept back: linux-generic linux-generic-hwe-24.04 linux-headers-generic linux-headers-generic-hwe-24.04 linux-image-generic linux-image-generic-hwe-24.04

Each needs a new kernel package, like linux-image-6.8.0-149-generic. apt upgrade installs the 11 new packages, so all 6 go through: 88 + 6 = 94. Neither one removes anything; apt full-upgrade (apt-get dist-upgrade) is the upgrade that may also remove packages.

6Prove it: flip one switch

The whole upgrade difference is one key, APT::Get::Upgrade-Allow-New. -o sets one config option for a single run. Turn the key off for apt and you get apt-get's numbers; turn it on for apt-get (or pass --with-new-pkgs) and you get apt's:

apt -s -o APT::Get::Upgrade-Allow-New=0 upgrade | grep upgraded, 88 upgraded, 0 newly installed, 0 to remove and 6 not upgraded. apt-get -s -o APT::Get::Upgrade-Allow-New=1 upgrade | grep upgraded, 94 upgraded, 11 newly installed, 0 to remove and 0 not upgraded. apt-get -s --with-new-pkgs upgrade | grep upgraded, 94 upgraded, 11 newly installed, 0 to remove and 0 not upgraded.

7show: for people vs for scripts

apt-cache show prints every field of the package index. apt show drops the checksums (MD5 and SHA hashes that prove the download is not corrupted) and the file path, and adds what a person checks before installing:

apt show cowsay 2>/dev/null | wc -l 21 apt-cache show cowsay | wc -l 27 apt-cache show cowsay | grep ^Size Size: 18572 apt show cowsay 2>/dev/null | grep -E '^(Download-Size|APT-Sources)' Download-Size: 18.6 kB APT-Sources: http://archive.ubuntu.com/ubuntu noble/universe amd64 Packages

Same number, two formats: 18572 bytes ÷ 1000 = 18.6 kB (kilobytes).

8Two quiet ones: cache and lock

Two more keys exist only in the Binary::apt scope:

apt-config dump | grep -i -E 'Keep-Downloaded|Lock::Timeout' binary::apt::APT::Keep-Downloaded-Packages "0"; binary::apt::DPkg::Lock::Timeout "120";
  1. After a successful install, apt deletes the downloaded .deb package files from /var/cache/apt/archives. apt-get leaves them there.
  2. Only one program can install packages at a time: it holds the dpkg lock (unattended-upgrades often holds it right after boot). apt waits up to 120 s for it; apt-get has no wait set and stops with an error at once.

9Which one to type

# at the prompt: apt
apt update
apt install cowsay
apt upgrade
apt full-upgrade
apt search cowsay
apt show cowsay
apt list --upgradable
# in scripts, Dockerfiles, CI: apt-get / apt-cache
apt-get update
apt-get install -y cowsay
apt-get upgrade --with-new-pkgs
apt-get dist-upgrade
apt-cache search cowsay
apt-cache show cowsay

CI (continuous integration) is a server that builds and tests code on every push. Nobody watches it: a progress bar is noise there, and the output must not change between versions. A Dockerfile is the same case:

FROM ubuntu:24.04
RUN apt-get update && apt-get install -y curl

10Common mistakes

apt in a script or Dockerfile. It prints the stable-CLI warning on stderr, and its output may change in the next release. Fix: apt-get for install and upgrade, apt-cache for search and show.

Expecting apt-get upgrade to install a new kernel. It holds back every upgrade that needs a new package (6 kernel packages above). Fix: apt-get upgrade --with-new-pkgs, or apt-get dist-upgrade when removals are fine.

apt-get list. list exists only in apt:

apt-get list E: Invalid operation list

Reading checksums from apt show. It drops MD5sum and the SHA fields. Fix: apt-cache show.

apt-get -s upgrade | tail -1 to get the summary line. With -s the plan ends with Conf ... lines, so tail -1 prints one of those. Fix: grep upgraded,.

Summary

  1. apt, apt-get and apt-cache share one library, libapt-pkg; apt only flips defaults in the Binary::apt scope.
  2. apt adds color, progress, a pipe warning, a trimmed show, a 120 s lock wait and deletes downloaded .debs.
  3. apt upgrade installs new packages an upgrade needs; apt-get upgrade holds those back unless you pass --with-new-pkgs.
  4. Type apt at the prompt; write apt-get and apt-cache in scripts, Dockerfiles and CI.
